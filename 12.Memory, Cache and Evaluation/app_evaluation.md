# 114. Evaluation of Chatbot – **Data Input Creation with Schema**

### 🎯 Goal

Create **structured, repeatable test data** for chatbot evaluation so metrics are **automatable**, not subjective.

---

## Why schema-based data matters

From the whiteboard in the PDF, evaluation always revolves around:

```
Input  → Chatbot → Output
          ↑
     Compare with Ground Truth
```

If inputs and outputs are not **structured**, evaluation breaks.

---

## Typical Evaluation Dataset Schema

Based on the subtitles, each **data point** contains:

```json
{
  "input": {
    "question": "What is RAG?"
  },
  "reference_output": {
    "answer": "RAG combines retrieval with generation to ground LLM responses."
  },
  "metadata": {
    "topic": "RAG",
    "difficulty": "basic"
  }
}
```

### Core fields (must-have)

| Field                     | Purpose                       |
| ------------------------- | ----------------------------- |
| `input.question`          | User query                    |
| `reference_output.answer` | **Ground truth**              |
| `output.answer`           | Generated by chatbot          |
| `metadata`                | Optional filtering & analysis |

This is exactly what later feeds:

* **LLM-as-a-Judge**
* **Correctness**
* **Concision**
* **Groundedness**

📌 As shown in the flow diagram, **reference output = anchor for all metrics**

# 115. Evaluation of Chatbots – **Defining Metrics (LLM as a Judge)**

This is the **heart of modern LLM evaluation**.

---

## Why traditional metrics fail

BLEU, ROUGE ❌
Exact match ❌

LLM outputs are:

* Non-deterministic
* Semantically correct but lexically different

Hence 👉 **LLM evaluates LLM**

---

## Metric 1: Correctness (LLM-as-a-Judge)

### Concept

An LLM plays the role of an **expert evaluator**, guided by a **strict prompt**.

From the subtitle:

> *“You are an expert professor specializing in grading student answers.”*

---

### Evaluation Prompt Pattern

```
You are grading the following question.
Here is the question:
{input}

Here is the ground truth answer:
{reference_output}

Here is the predicted answer:
{output}

Respond with Correct or Incorrect.
```

### Implementation logic

```python
return True if response == "Correct" else False
```

📌 Key points:

* **Temperature = 0** → deterministic judgment
* Judge model can be **different from generator**
* Output must be **boolean** for aggregation

This is clearly described in the correctness function explanation 

---

## Metric 2: Concision (Rule-based)

Not all metrics need LLMs.

### Logic used:

```python
len(output) < 2 * len(reference_output)
```

✔ Checks verbosity
✔ Fast
✔ Cheap

This shows a **hybrid evaluation strategy**:

* LLM-based (semantic)
* Rule-based (structural)

---

## Why this approach scales

You can easily add:

* Relevance
* Hallucination
* Safety
* Tone
* Style adherence

Each as a **function**, not hard-coded logic.

# 116. Evaluation of Chatbots – **Running Metrics with Different LLMs**

Now comes the **experiment phase** 🚀

---

## Step 1: Define your chatbot function

```python
def my_app(question, model):
    return openai.chat.completions.create(...)
```

This represents:

> “My chatbot system under test”

---

## Step 2: Define evaluation target

```python
def lhs_target(input: str):
    return my_app(input, model="gpt-4o-mini")
```

This abstraction allows:

* Swapping models
* Reusing the same dataset
* Clean experiment separation

---

## Step 3: Run evaluation

```python
client.evaluate(
  target=lhs_target,
  dataset_name="chatbot_eval_dataset",
  evaluators=[correctness, concision],
  experiment_prefix="gpt-4o-mini-chatbot"
)
```

What happens internally:

1. Each dataset question is sent to chatbot
2. Output is generated
3. Each metric is applied
4. Results logged in **LangSmith UI**

---

## Step 4: Compare Multiple LLMs

From the subtitles:

* Run same dataset with:

  * GPT-4o-mini
  * GPT-4-Turbo
* Compare scores side by side

Example outcome:

| Model       | Correctness | Concision |
| ----------- | ----------- | --------- |
| GPT-4o-mini | 0.60        | 0.40      |
| GPT-4-Turbo | 0.60        | 0.20      |

📌 Insight: **Better model ≠ better UX**
Conciseness dropped even when correctness stayed same.
